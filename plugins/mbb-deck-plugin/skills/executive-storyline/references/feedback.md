# Giving feedback on a storyline

First establish the document type (team alignment, recurring update, board, decision pre-read, external, documentation, keynote) and judge against that bar. A team-alignment note is not failed for lacking a decisions section.

## The three-part review

1. **Overall verdict.** Two explicit judgments:
   - Is there one clear governing thought, stated early, at insight or so-what level?
   - Does the chosen structure fit the audience and how controversial the message is?
2. **Element by element.** Walk the storyline top to bottom:
   - the opening - situation, complication, question and answer present and sharp?
   - each argument - content or process, logical level, MECE across arguments, evidence assigned, numbers defined
   - the close - decision needs, next steps
   Quote the original wording whenever you propose a rewrite.
3. **Top three improvements.** The three changes that would most strengthen the storyline, in priority order.

## Six tests to run on every draft

| Test | How | What to report |
|---|---|---|
| Titles-only read | Read only the action titles or lead sentences, in sequence | Whether they tell the story, and where the thread breaks |
| Content/process scan | Classify each statement as governing thought, content or process | Every process statement that is not a next step |
| Insight check | Place each message on the four levels (data, summary, insight, so what) | Whether the governing thought is a recommendation or a summary of findings |
| MECE check | Name the dimension of each level | Overlaps (two dimensions mixed) and gaps (a member missing) |
| Count and order check | Count the arguments per level; name the order used | More than five on a level; an order that cannot be named |
| Number check | Follow each figure through the document | Figures without basis, period or baseline; figures that differ between places |

## Thirteen common weaknesses

| # | Weakness | What it looks like | Fix |
|---|---|---|---|
| 1 | Work-order narrative | The document retells the project chronologically | Invert into pyramid order |
| 2 | Buried governing thought | The recommendation appears on the last page | State it in the opening; let the document substantiate it |
| 3 | Summary sold as insight | Organized facts without an implication | Force the so what and the CEO test |
| 4 | Process padding | Activities presented as content | Cut, or convert into one next-steps line |
| 5 | Argument sprawl | Six or more parallel arguments | Group into three |
| 6 | Mixed logical levels | Evidence presented as a new argument | Fold it under the argument it supports |
| 7 | Overlaps and gaps | A level mixes two dimensions or misses an obvious member | One dimension per level, all members covered |
| 8 | Missing or artificial complication | The document never says why this matters now | Add a real complication and its question |
| 9 | Wrong baseline | Impact stated against a reference the decision maker does not use | Restate against their baseline and explain the difference |
| 10 | Missing decision needs | The document ends without an ask, or with "let's discuss" | A decisions section: which, by when, why now |
| 11 | Executive summary drift | The summary tells a different story than the document, or its numbers differ | Rebuild it from the action titles |
| 12 | Written for the writer | The structure mirrors the team's workstreams, not the audience's decision | Restart from audience and objective |
| 13 | Generic text | Smooth sentences that say nothing specific | Replace each with the concrete point, number or decision |

## Tone

- Direct and specific. "The opening is weak" helps nobody; quote the sentence and write the replacement.
- If the governing thought is missing or wrong, say that first. Everything else is downstream of it.
- Say what works, briefly. Do not manufacture issues to look thorough.
- Do not supply facts. If a rewrite needs a number the draft lacks, leave a named gap.
